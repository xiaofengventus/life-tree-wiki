# 分形漫游树 · 3D 实验（方案版本 B）

OneZoom 式演化树的 3D 版本。**纯本地实验**：不接入正式页面、不加路由、不碰数据库、
不改 `server/*` 与 `functions/api/*`。跑起来看效果，觉得对了再谈"转正"。

---

## 跑起来

```bash
# 项目根目录
npx vite --config experiments/fractal-3d/vite.config.mjs
```

然后打开 <http://localhost:5199/>

> 为什么要单独一份 vite 配置：根配置的缓存目录是 `node_modules/.vite`，装完新依赖后
> vite 会去清空它，而本机沙箱的 safe-delete 会在批量删除时拦截，dev server 直接起不来。
> 这份配置把 `root` 和 `cacheDir` 都挪进实验目录，绕开这个坑。

### 单测

```bash
node --test experiments/fractal-3d/layout3d.test.mjs
```

## 算法：三条规则

目标是「从任意深度放大进去，形态都一样」——做到了，缩放才是"无限"的。

**1. 半径几何增长**　`r(d) = radiusBase × K^d`

自相似的充要条件。每往下一层所有长度都乘 K，所以"放大 K 倍"后画面与上一层完全一致。

**2. 方向在锥内按球冠面积均匀铺开**

每个节点持有方向 `dir` 和锥半角 `spread`（= 它的整棵子树被约束在这个锥里）。
子节点方向按面积均匀排开，方位角用黄金角错开避免相邻打架。

**3. 角度空间按等立体角分配**　`cos(αᵢ) = 1 − wᵢ(1 − cos αp)`

`w` 是子节点叶子数占比。球冠面积 ∝ `1−cos α`，所以这条保证 **Σ 子立体角 = 父立体角**：
权重大的分支自动拿到更大展开空间。

**4. 用「根锥余量」约束子锥**　`βmax = rootSpread − angle(dir, 根轴) − αi`

保证子锥始终落在根锥内（半球模式下就是"永远不长到海面以下"）。

> 这一条踩过两个坑，都留下了：
> - 一开始拿**父锥**约束（`β ≤ spread − α`），权重极不均的树里最大分支能吃掉父锥的
>   绝大部分（这棵树真核占 83%、锥角 80°），其余分支瞬间被压到轴上 ——
>   表现出来是"树上部一大坨全堆在顶上"。
> - 改放松成"铺满父锥 + 事后投影回锥面"，又制造了一个**锥面吸引子**：
>   枝条一旦被投影到锥面就会沿着它滑行，深层节点全贴着海面走。
> - 最后换成根锥余量：每个节点无论多深都还剩它该有的那份角度空间，两层毛病都没了。

**5. 子节点按叶子数降序排**

方向是按序号均匀铺开的，"谁排前面谁更靠近锥轴"。让最大分支居中，
它才不会被挤到锥边、然后连着几十层后代一起偏在一边。

### 关于 `depthExponent`（面板上的"自相似度"）

`r(d) = R × K^(d^p)`

- `p = 1`：严格几何，跨度大。这棵树 107 层，最外层半径是根部的 **3770 倍** ——
  看全树时内部会糊成一团，只剩外面一层壳。
- `p = 0.85`（**默认**）：跨度降到 ~49 倍，整棵树的层次一眼看得清。
- 越深的树越需要这个旋钮。浅树（20 层以内）用 1.0 完全没问题。

## 泛化：刻意没有为某一棵树调参

这是重点。布局吃的是**用户自己造的树**，形状完全不可控，所以：

- `normalizeTree()` 把任意输入统一成 `{ uid, text, image, children }`：
  兼容 `{data:{uid,text}}` / `{label}` / `{name}` / 裸节点 / 缺 uid（按路径补，保证可复现）/
  `children` 不是数组 / 重复引用造成的环（WeakSet 切断）/ 超大输入（nodeLimit 兜底）。
- 页面支持**下拉切换 16 棵真实树**，也支持**直接拖一个 json 进来**。
- 单测里跑了 `data/` 下**全部 16 棵树**（3 节点 ~ 2363 节点），断言节点数、无 NaN、
  半球约束、方向归一化。

已验证的规模跨度：**3 / 16 / 21 / 23 / 25 / 45 / 50 / 61 / 86 / 177 / 235 / 302 / 326 / 407 / 2363** 节点。

## 数据

`data/*.json` 是脚本从线上公开 API 拉的（`api/trees/:uid`），格式：

```json
{ "uid": "T000021", "title": "life-tree", "nodeCount": 2363,
  "document": { "root": { "data": { "uid": "...", "text": "..." }, "children": [] } } }
```

线上 API 没有 CORS 头，本地页面直接 fetch 会被拦，所以走本地文件。
需要补数据时重新跑一次抓取脚本即可。

## 已知边界

- **不能绕树转一圈看背面** 的问题已经不存在了 —— 3D 版就是真 WebGL，随便转。
- 性能：2363 节点 = 1 个 `InstancedMesh`（节点）+ 1 个 `LineSegments`（枝），
  共 2 个 draw call。布局本身 ~10ms。headless 截图里帧率低是 SwiftShader 软件渲染，
  真机 GPU 不受影响。
- 标签还没做（悬停有 tooltip，常显标签需要 `CSS2DRenderer` 或叠加层）。
- 折叠（`collapsedIds`）算法层已经支持并测过，UI 还没接。
- 场景层（海 / 天 / 星）是氛围，固定 ~10 个元素，与节点数无关。
