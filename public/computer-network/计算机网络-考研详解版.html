01物理层：编码方式与信道容量极限

物理层回答两个问题：比特怎么变成信号（编码），一条信道最多能跑多快（奈氏准则与香农公式）。这两块是考研物理层的全部考点。

1.1 三种经典编码（以比特串 1 0 1 1 0 0 1 为例）

码元与比特：比特率 = 波特率 × log₂(每码元离散状态数 V)。若 1 个码元携带 4 bit（V=16），2400 Baud 的码元速率 = 9600 bps 比特率。曼彻斯特编码 V=2 且每比特两个码元 → 效率 50%。

1.2 两个极限公式（必背 + 会算）

公式内容典型例题
奈氏准则（无噪声）理想低通信道极限波特率 = 2W Baud（W 为带宽 Hz）；极限比特率 = 2W·log₂V带宽 3kHz、16 种码元：C = 2×3000×log₂16 = 2×3000×4 = 24 kbps
香农公式（有噪声）信道极限容量 C = W·log₂(1 + S/N)，其中 S/N 为线性信噪比带宽 3kHz、信噪比 30dB（=10^(30/10)=1000 倍）：C = 3000×log₂1001 ≈ 29.9 kbps
dB 与倍数换算：dB = 10·lg(S/N)。30dB→1000 倍，20dB→100 倍，10dB→10 倍。奈氏只限制波特率（决定用多高阶的调制去逼近），香农限制的是比特率上限——两者取小者为实际可达速率。

02数据链路层：组帧、差错检测（CRC 必考计算）

链路层把比特流切成「帧」。三个问题：帧边界怎么定（组帧）、错了怎么发现（检错）、发现后怎么办（重传，见第 3 节）。

2.1 四种组帧方法

方法原理缺陷 / 使用
字符计数法帧首用一个计数字段标明帧总长度计数字段一旦出错，后面全错 —— 很少用
字节填充法用 SOH/EOT 做定界符；数据里出现同值字节前插转义字符 ESC（PPP 异步传输）接收方删除转义还原；复杂度低
比特填充法用 01111110 定界；发送方对数据中每 5 个连续 1 自动插一个 0（HDLC；PPP 同步传输同思想）接收方每遇 5 连 1 删后面的 0 —— 最常用
违规编码法用编码中「不可能出现」的电平组合做边界（如曼彻斯特的「高高」「低低」）只适用于有冗余电平的编码
比特填充计算题：数据 011011111111000 → 发送方扫描，每 5 连 1 后插 0：0110111110111000（第 8 位起出现 5 个 1，插 0 后剩余的 1 不再连续）。反向考法：接收方收到帧，去 0 还原。

2.2 CRC 循环冗余校验（计算大题套路）

步骤：① 生成多项式 P 为 r+1 位 → 在数据 M 后补 r 个 0；② 对补零后的数做模 2 除法（异或不借位）；③ 余数 R（r 位，不足左补 0）拼在 M 后发送。接收方用收到的帧再除 P，余数为 0 即认为无错。

例：数据 M = 101001（6 位），生成多项式 P = 1101（r = 3）→ 补 3 个 0 得 101001000

  窗口 1010 ≥ 1101 → 商1，1010⊕1101 = 0111，落下一位 → 1110

① 余数位数 = r = 多项式最高次数（P 有 r+1 位）；余数不足 r 位要左补 0（本例恰好 001）。② CRC 只能检错不能纠错（海明码才能纠错）。③ 循环冗余的「循环」指：合法码字循环移位后仍是合法码字。④ 生成多项式两端必须为 1。

2.3 海明码与最小海明距离

  • 校验位个数：信息 m 位需校验位 k 位，满足 2k ≥ m + k + 1。例：m=4 → k=3（2³=8 ≥ 4+3+1=8，恰好成立）；m=8 → k=4。
  • 校验位位置：放在 2 的幂次号上（1,2,4,8,…），每个校验位负责其二进制位号中含该权重的所有位（偶校验分组异或）。
  • 最小海明距离 d：任意两个合法码字的最小异或位数。 检错 e 位需 d ≥ e+1；纠错 t 位需 d ≥ 2t+1。d=3 → 可检 2 位或纠 1 位；d=4 → 检 3 位或纠 1 位同时检 2 位。
CRC 与海明码分工：链路层实际用的是 CRC（检错 + 丢弃重传）；海明码用在内存 ECC 等不能重传的场景。考试爱考「CRC 余数计算」「海明距离与检纠错能力的关系」。

03可靠传输：停等 / 回退 N（GBN）/ 选择重传（SR）

「自动重传请求 ARQ」的三个档位。考研计算核心是窗口大小与序号比特数 n 的约束；TCP 实际用的是「SR 思想 + 累计确认」的混合体。

对比项停等协议回退 N（GBN）选择重传（SR）
发送窗口 W11 < W ≤ 2n − 1W ≤ 2n−1（发送=接收）
接收窗口11> 1（= 发送窗口）
确认方式逐个确认累计确认：ACK n 表示「n 及之前全收到」逐个确认
出错处理超时重传该帧某帧错 → 该帧及之后已发的全部重传只重传真正丢失/出错的帧；接收方缓存乱序到达的正确帧
信道利用率最低 = TD/(TD+RTT+TA)高高且重传代价小

停等信道利用率 = TD / (TD + RTT + TA)，连续 ARQ 利用率 ≈ min(1, W·TD/(TD+RTT+TA))。计算题先算发送时延（帧长/带宽）、再算传播时延，别漏 ACK 的发送与传播时延（题目说「忽略确认帧开销」才算 0）。

04以太网：帧格式与 CSMA/CD（最小帧长推导）

经典共享式以太网（半双工）靠 CSMA/CD 仲裁信道；交换式全双工以太网不再冲突，但帧格式与 MAC 规则沿用至今。

4.0 以太网演进与标准命名（先看懂 "10BASE-T" 这类写法）

标准速率传输媒介 / 拓扑要点
10BASE5（粗缆）10M粗同轴电缆 · 总线型首代以太网，AUI 收发器，最长 500m/段
10BASE2（细缆）10M细同轴电缆 · 总线型廉价易断，185m/段
10BASE-T10M双绞线 · 星型（Hub）拓扑革命：总线→星型；Hub 是物理层设备，仍是同一个冲突域
100BASE-TX100M五类双绞线 · 星型（交换机）快速以太网；交换机普及 → 全双工 → CSMA/CD 退役
1000BASE-T1G超五类/六类双绞线千兆下行到桌面；1000BASE-X 系列走光纤（LX 长距 / SX 短距）

  • 双工的演变：总线/Hub 半双工必须 CSMA/CD；交换机每个口独立冲突域 + 全双工后不再需要 CSMA/CD（但为兼容半双工模式，标准仍保留该机制）。

4.2 CSMA/CD：边发边听，冲突即停

  • 多址接入 MA：总线共享，大家抢；载波侦听 CS：发前先听，闲才发；冲突检测 CD：边发边听，检测到冲突立即停发并发出 48 bit 强化干扰信号。
  • 为什么有最小帧长：发完最后 1 bit 之前必须知道有没有冲突。最坏情况：两台主机在总线两端（相距 τ），A 发出的信号快到 B 时 B 开始发 → 冲突信号再花 τ 回到 A → A 至少要持续发送 2τ（争用期）。
  • 经典以太网：τ ≤ 25.6 μs → 争用期 2τ = 51.2 μs → 10 Mbps 下最小帧长 = 10M × 51.2μs = 512 bit = 64 B。这正是数据字段下限 46 B 的来源。
  • 截断二进制指数退避：第 i 次冲突后，从 {0,1,…,2min(i,10)−1} 随机选 k，等待 k×2τ 再试；16 次失败放弃并报错。i 越大等待窗口指数越大 → 自动错开。
计算题模板：求 1 Gbps、争用期 512 比特时间（千兆保留 512 bit 时隙）场景下跨距 → 最大网段长度 = 传播速率(2×10⁸ m/s) × 512/10⁹ ÷ 2。核心公式只有一条：最小帧长（bit）≥ 2 × 传播时延 × 数据率。全双工交换式以太网没有 CSMA/CD，不受此限制。

05VLAN：802.1Q 帧格式、端口类型与 VLAN 间路由

VLAN 把一台交换机切成多个逻辑广播域。跨交换机的 VLAN 流量要打标签，VLAN 之间通信要靠三层——单臂路由或三层交换机。

5.2 交换机端口类型（华为）收发规则

5.3 VLAN 间路由：单臂路由 vs 三层交换

三层交换机方案：为每个 VLAN 建 SVI（Vlanif10 / Vlanif20 虚接口当网关），芯片级「一次路由、多次交换」，同一台交换机内 VLAN 间流量不再绕路由器 —— 大型园区首选。单臂路由缺点：所有 VLAN 间流量挤一条物理链路，带宽瓶颈 + 单点故障。

06STP 深化：BPDU、端口状态时间轴、选举规则全解 + 链路聚合

前页讲过选举大流程，这里补齐考试细节：BPDU 字段、端口五个状态的时间开销、RP/DP 的完整比较规则、STP/RSTP/MSTP 三代差异。

6.1 BPDU 关键字段与三个计时器

6.2 RP / DP 选举的完整比较顺序（考试逐条比）

  • 根端口 RP（每台非根桥一个）：依次比较 ① 根路径开销最小 → ② 对端桥 ID 最小 → ③ 对端端口 ID 最小 → ④ 本端端口 ID 最小。
  • 指定端口 DP（每网段一个）：依次比较 ① 根路径开销 → ② 本端桥 ID → ③ 本端端口 ID。根桥所有端口天然是 DP。
  • 开销表（华为缺省 802.1t 标准）：10M=2000，100M=200，1G=20，10G=2（开销 = 2×10¹⁵/带宽，取整）。
常见坑：① 优先级必须设为 4096 的倍数；② 优先级相同比 MAC，MAC 小的当根——实际组网手动把核心交换机优先级调小；③ 优先级为 0 的端口不参与 STP 选举；④ 根桥上的端口不可能被阻塞。

6.3 链路聚合（Eth-Trunk）

模式机制特点
手工模式人工指定成员口，不交互 LACP 报文配置简单；无法感知对端异常链路
LACP 模式成员口互发 LACPDU 协商：比较系统优先级+MAC 选「主动端」，主动端按端口 ID 选活动口能检测链路故障/错接，支持 M:N 主备；生产首选

三大收益：带宽叠加、负载分担（按源目 MAC/IP 哈希分流，单条流量不走两条链路——保证不乱序）、可靠性（单链路断流量秒切其余链路）。所有成员口必须同速率同双工同类型，聚合口在 STP 眼里是一条逻辑链路。

6B.2 为什么用 CSMA/CA 而不能用 CSMA/CD？

原因 / 对比项有线 CSMA/CD无线 CSMA/CA
能否边发边听能（同轴/双绞线收发可分）不能：自身发射信号比接收信号强百万倍，发送时接收机被淹没，无法检测冲突
冲突发生在哪发送端立刻感知接收端；发送端根本不知道（隐藏站点问题）
策略检测到冲突就停、退避重试尽量避免冲突 + 每一帧都要 ACK 确认，收不到 ACK 就当冲突处理
帧间间隔—SIFS（最短，用于 ACK/CTS 抢占）< PIFS < DIFS（数据帧前必须等）——间隔越短优先级越高
  • 基本流程：侦听信道忙 → 等 DIFS → 信道空闲 → 退避计时器递减（争用窗口内随机值）→ 计到 0 才发 → 收到 ACK → 下一帧；超时未收 ACK → 退避窗口翻倍重试。
  • RTS/CTS 机制（解决隐藏站点）：发大帧前先发 RTS 申请，AP 回 CTS 全网广播——所有听到 CTS 的站点（包括听不到发送方的隐藏站点）静默 NAV 时间，之后才发数据。

转发模式数据路径优缺点
直接转发STA → AP 就地脱 CAPWAP → 本地交换机 → 网关（业务数据不过 AC）效率高；但 AC 管不到用户流量，策略下发麻烦
隧道转发STA → AP → CAPWAP 封装送 AC → AC 解封装出网AC 集中管控/审计；AC 与隧道成带宽与故障瓶颈
STA 接入五步：① 扫描（被动收 AP 周期广播的 Beacon 帧 / 主动发 Probe Request）→ ② 链路认证（开放系统 / WPA2-PSK / 802.1X）→ ③ 关联 Association → ④ DHCP 取地址 → ⑤ 用户认证（Portal/802.1X）后上网。安全演进：WEP（已破解）→ WPA（TKIP）→ WPA2（AES-CCMP）→ WPA3（SAE）。

07IPv4 首部逐字段 + 分片计算

IP 首部 20 字节起，是全网计算题的高频素材。重点记忆三个「单位」：首部长度按 4B、总长度按 1B、片偏移按 8B。

版本 4bit 首部长 4bit 区分服务 8bit 总长度 16bit 标识 16bit 标志 3bit 片偏移 13bit TTL 8bit
生存时间 TTL 协议 8bit 首部校验和 16bit 源 IP 地址 32bit 目的 IP 32bit
4=IPv4单位4B，最大60BQoS 标记首部+数据，单位1B，上限65535 同一数据报的分片相同保留·DF·MF单位8B每过一路由器减1
  • TTL：不是时间！是跳数上限。减到 0 丢弃并回 ICMP Type=11（超时）——traceroute 的原理就是故意发 TTL=1,2,3…的包。
  • 协议号：1=ICMP，6=TCP，17=UDP，89=OSPF（对比：端口是传输层的，协议号是网络层的分用依据）。
  • 首部校验和只校验首部且每跳重新计算（TTL 变了）；数据部分不校验——数据完整性由传输层管。
分片例题：一个 IP 数据报总长度 3820 B（首部 20 B，数据 3800 B），经过 MTU=1500 的链路。

每片可装数据 ≤ 1500 − 20 = 1480 B（每片都要带完整 20B 首部）
3800 = 1480 + 1480 + 840

片1：总长 1500 · 数据 1480 · 片偏移 0/8 = 0   · MF=1
片2：总长 1500 · 数据 1480 · 片偏移 1480/8 = 185 · MF=1
片3：总长 860  · 数据 840  · 片偏移 2960/8 = 370 · MF=0（最后一片）

三片「标识」字段完全相同（重组时归队）；重组只在最终目的主机进行，中间路由器可对分片再分片。
① DF=1（不许分片）但超过 MTU → 丢弃并回 ICMP「目的不可达·需要分片」（PMTU 发现原理）。② 片偏移单位是 8B，所以除最后一片外每片数据长度必须是 8 的倍数。③ 分片丢失 → 整个数据报重传（传输层以为丢了一个报文段）。

8.2 VLSM 变长子网划分（完整例题）

例：将 192.168.1.0/24 划分给四个网段：A 需 100 台主机、B 需 50 台、C 需 20 台、D 是路由器互联链路。

思路：先算「可用主机数 = 2^(32−前缀) − 2」，从需求大的开始排，杜绝地址碎片
  A: 100 ≤ 2⁷−2=126 → /25（掩码 255.255.255.128）→ 192.168.1.0/25   可用 .1 ~ .126
  B: 50  ≤ 2⁶−2=62  → /26（255.255.255.192）     → 192.168.1.128/26 可用 .129 ~ .190
  C: 20  ≤ 2⁵−2=30  → /27（255.255.255.224）     → 192.168.1.192/27 可用 .193 ~ .222
  D: 点对点只需 2   → /30（255.255.255.252）     → 192.168.1.224/30 可用 .225 ~ .226

验算不重叠：块大小分别为 128 / 64 / 32 / 4，边界 .0 · .128 · .192 · .224 严格对齐 ✓
速算表：/25→126，/26→62，/27→30，/28→14，/29→6，/30→2；块大小（相邻子网间隔）= 256 − 掩码末字节。掩码 255.255.255.192 的块大小 = 256−192 = 64。判断 192.168.1.100/26 属于哪个子网：100 ÷ 64 = 1 余 36 → 属于 192.168.1.64/26（网络地址 64、广播 127）。
CIDR 聚合例题：把 4 条路由 192.168.0.0/24 ~ 192.168.3.0/24 聚合成一条。

  0 → 00000000
  1 → 00000001      第三字节前 6 位相同 → 聚合为
  2 → 00000010      192.168.0.0/22（掩码 255.255.252.0）
  3 → 00000011

同网段判断：IP₁ AND 掩码 == IP₂ AND 掩码 → 同网段（同网段直接 ARP 交付，否则发给网关）。

10.1 RIP 的环路问题与五大对策

RIP「基于传闻」：A 从 B 学到的路由又会被 B 从 A 处学回去 —— 拓扑变化时形成计数到无穷。对策：

对策原理
最大跳数 16把「无穷大」定义为 16 跳，计数到 16 停止
水平分割从某接口学来的路由，不再从该接口通告回去

抑制计时路由失效后先抑制定时间，防止轻信邻居的过时好消息

12传输层：TCP / UDP 首部逐字段

12.1 UDP 首部（固定 8 字节，就这么点）

源端口 16bit 目的端口 16bit 长度 16bit 校验和 16bit
可全 0（无需回包）分用依据首部+数据（单位字节）可选；校验需加 12B 伪首部
  • 无连接、不保证可靠、不排序、无拥塞控制 —— 报文应用全交付（面向报文，应用给多长发多长）。
  • 伪首部：临时拼接「源IP+目的IP+0+协议号(17)+UDP长度」参与校验和计算但不传输 —— 让 UDP 顺带验证「IP 有没有把包送错主机」。

12.2 TCP 首部（固定 20 字节 + 可选）

源端口 16bit 目的端口 16bit 序号 seq 32bit
确认号 ack 32bit（期望收到的下一个字节序号） 数据偏移 4bit
保留 6bit URG ACK PSH RST SYN FIN 窗口 16bit（接收方通告 rwnd） 校验和 16bit
紧急指针 16bit 选项（最长 40B：MSS、窗口扩大、SACK、时间戳）+ 填充
  • seq / ack 单位是「字节」不是报文段 —— 每个字节都有编号；ack = 已正确收到的最后字节号 + 1（累计确认）。
  • 数据偏移：首部长度，单位 4B（最大 60B，与 IP 首部一个套路）。
  • 六个标志位逐个记：URG 紧急位有效 · ACK=1 时 ack 字段才有意义（握手后恒为 1）· PSH 尽快上交应用 · RST 重置连接（端口未监听就回它）· SYN 请求建连 · FIN 请求释放。
  • 窗口：接收方通告还能接收多少字节（rwnd）→ 流量控制的数据载体；MSS 常见 1460 = 1500 − 20(IP) − 20(TCP)，在 SYN 报文的选项里协商。
对比题：TCP 面向字节流（发送多少、怎么分块由 TCP 决定，应用看到的是流）；UDP 面向报文。TCP 首部固定 20B、UDP 8B、IP 20B —— 最小总开销 28B vs 48B。

13TCP 可靠传输：确认重传、超时计算（RTT 估计公式）

  • 序号 + 确认：按字节编号；接收方采用累计确认（ACK n = n 前全收到），失序段先缓存（SACK 可精确报告洞的位置）。
  • 超时重传：每发一个段启动计时器，超时未确认就重传，并把超时时间 RTO 加倍（每连续超时一次翻倍，防止拥塞雪上加霜）。
  • 快速重传：收到 3 个重复 ACK（不必等超时）立即重传缺失段 —— 后面拥塞控制里的「快重传」就靠它触发。
RTO 自适应算法（RFC 6298，考研考过）：
  每测得一个新样本 RTT样：
    RTTs（加权平均往返时间） = (1 − α) × 旧RTTs + α × RTT样     推荐 α = 1/8
    RTTd（偏差）            = (1 − β) × 旧RTTd + β × |RTTs − RTT样|  推荐 β = 1/4
    RTO = RTTs + 4 × RTTd

例：RTTs=100ms，新样本 80ms → RTTs = 7/8×100 + 1/8×80 = 97.5ms
    （样本值围绕真实值波动，加权平均滤除抖动；首测时 RTTs=样本，RTTd=样本/2）

14流量控制与拥塞控制（四算法 + cwnd 曲线必考）

流量控制是点对点的（不让发送方压垮接收方，载体 = rwnd）；拥塞控制是全局的（不让发送方压垮网络，载体 = cwnd）。实际发送窗口 = min(rwnd, cwnd)。

算法触发条件动作
慢启动连接刚建立 / 超时后重启cwnd=1（或初始窗口 10），每轮指数翻倍，直到 ≥ ssthresh
拥塞避免cwnd ≥ ssthresh每轮线性加 1（加法增大）
快重传收到 3 个重复 ACK不等超时，立即重传丢失段
快恢复伴随快重传ssthresh=cwnd/2，cwnd=新 ssthresh（乘法减小后继续线性）
超时与重复 ACK 的动作不同：超时 → cwnd 归 1 重新慢启动；3 重复 ACK → 减半不归 1（说明网络还在送 ACK，没瘫）。初值 ssthresh 通常 16（教材图），实际 Linux 初始 cwnd=10。捎带：发送窗口 min(rwnd, cwnd)，两端题目常设 rwnd=4000、cwnd=2000 之类，答案是 min。

15三次握手为什么是三次？TIME_WAIT 为什么等 2MSL？

15.1 三次不可省（标准答案）

  • 两次不够：若只有 SYN→SYN+ACK 两次，服务端发出 SYN+ACK 后即认为连接建立；若这个报文滞留在网络中，客户端迟迟不回 ACK，服务端就一直干等 —— 资源泄漏（历史上著名的「已失效连接请求」问题）。
  • 四次冗余：第三次 ACK 可与第一个数据段合并发送，四次浪费一个 RTT。
  • 本质：三次是让双方的「发送能力 + 接收能力」都得到对方确认的最少次数，并同步双方初始序号 x、y。

15.2 SYN Flood 攻击与防护

攻击者海量伪造 SYN 且不回最后的 ACK，服务端半连接队列被塞满。防护：Syn Cookie（不保存半连接状态，把状态编码进序号回传）、缩短半连接超时、网关 SYN Proxy 代理。

15.3 四次挥手与 2MSL（TIME_WAIT）的两个原因

  • ① 保证最后的 ACK 可达：若最后的 ACK 丢了，对方会重传 FIN；主动方此时还在 TIME_WAIT 中就能重发 ACK。等满 2MSL 后才彻底关闭 ——「一个来回的保底时间」。
  • ② 让本连接的旧报文在网络中自然消亡：新连接（同四元组）不会收到旧连接迷路的报文。
MSL（最长报文段寿命）典型 2 分钟。主动关闭方才有 TIME_WAIT；大量 TIME_WAIT 是短连接服务的通病（内核参数 tcp_tw_reuse 等可缓解）。另外挥手也可能变「三次」：服务端若无数据要发，ACK 与 FIN 可合并（延迟确认机制）。

17FTP：控制与数据双连接、主动模式 vs 被动模式

FTP 控制连接整场保持（带外传送命令），数据连接按需建立、传完即断。明文传输 → 生产环境用 SFTP（SSH 通道）或 FTPS（TLS）。FTP 传输两种方式：文本模式（ASCII，自动换行转换）与二进制模式（IMAGE，逐字节原样）——传压缩包必须二进制。

20SSH 握手四步 vs Telnet；邮件系统推拉模型

20.1 SSH 会话建立（TCP 22 之上的应用层协议）

  1. 版本协商：双方交换 SSH-2.0 协议版本字符串。
  2. 算法协商：交换各自支持的加密/HMAC/压缩算法列表，取双方交集。
  3. DH 密钥交换：协商会话密钥（服务端发主机密钥指纹，客户端核对 known_hosts 防中间人）。
  4. 用户认证：password / publickey（RSA/ECC 密钥对，免密登录）/ keyboard-interactive；认证后进入加密会话通道（可复用跑 SCP/SFTP/端口转发）。
对比项Telnet（TCP 23）SSH（TCP 22）
数据全部明文（口令可被抓包）全程加密
认证方式仅口令口令 / 公钥密钥对
完整性强无HMAC 完整性校验
结论设备远程管理一律 Stelnet（SSH），Telnet 只在受控实验网保留

20.2 邮件：发送「推」、接收「拉」

发件方 UA →（SMTP 推）→ 发件服务器 →（SMTP 推）→ 收件服务器 →（POP3/IMAP 拉）→ 收件方 UA。SMTP（25，提交用 587）只管推、只能传 7 位 ASCII → MIME 扩展编码传附件。POP3（110）下载到本机（默认删服务器副本）；IMAP（143）邮件留在服务器、多端同步 —— 现代邮箱标配。Web 邮箱两端都是 HTTP。

21ACL 访问控制列表：分类、通配符掩码、匹配规则与部署位置

ACL 是路由器/交换机上的一条条「规则」，对经过的报文按五元组匹配后执行 permit / deny。它本身不是安全功能，是一张「匹配表」，被 traffic-filter、NAT、QoS、路由策略引用后才生效。

21.1 分类（华为编号段必背）

类型编号范围可匹配字段典型用途
基本 ACL2000 ~ 2999只看源 IP简单限制；靠近目的部署（避免误伤其他流量）
高级 ACL3000 ~ 3999源/目 IP + 协议号 + 源/目端口（五元组）精确控制；靠近源部署（尽早丢弃省带宽）
二层 ACL4000 ~ 4999源/目 MAC、以太帧类型二层过滤
用户自定义 ACL5000 ~ 5999报文任意偏移字节特殊协议
部署口诀（考试原题级别）：「基本 ACL 靠近目的，高级 ACL 靠近源」。原因：基本 ACL 只认源 IP，放太靠源会把该源发往其他目的的正常流量也拦掉。

21.2 通配符掩码（wildcard，与子网掩码写法不同！）

  • 规则：0 = 这一位必须严格匹配，1 = 这一位随意。不是掩码的反写那么简单 —— 中间可以不连续。
  • 192.168.1.0 0.0.0.255 → 匹配整个 C 段；192.168.1.1 0.0.0.0（或 host 192.168.1.1）→ 匹配单机；any = 0.0.0.0 255.255.255.255。
  • 反例：192.168.1.0 0.0.0.3 只匹配 192.168.1.0~3 这 4 个地址（偶数对齐的块，起止受 2ⁿ 约束）。

21.3 匹配流程与方向（inbound / outbound）

方向过滤时机思考方式
inbound（入方向）进入接口，先过滤再查路由表 —— 拦垃圾流量最省 CPU站在设备上问：「这个包从这进来该不该放？」
outbound（出方向）出接口前最后把关「离开设备的包该不该走这个口出去？」
# 例：禁止财务部(192.168.20.0/24)访问服务器网段(10.1.100.0/24)，其余放行
[FW] acl 3001
[FW-acl-adv-3001] rule 5 deny ip source 192.168.20.0 0.0.0.255 destination 10.1.100.0 0.0.0.255
[FW-acl-adv-3001] rule 100 permit ip          # 不写这句会被隐含 deny 全拦！
[FW] interface GigabitEthernet0/0/2
[FW-GigabitEthernet0/0/2] traffic-filter inbound acl 3001
三个必坑：① 每条 ACL 末尾隐含 deny any（华为部分场景默认 permit？——考试按「隐含 deny」答）；② 规则顺序即执行顺序，新规则要手动指定合适编号（步长 5，便于中间插规则）；③ ACL 不过滤路由器自身发出的报文（要过滤需用其他手段）；④ telnet/SSH 本身不下发 ACL 到业务口 —— 是应用到 VTY 线路。

22AAA：认证、授权、记账（RADIUS 全流程）

三 A回答的问题典型手段
认证 Authentication「你是谁？」账号口令 / 证书 / 802.1X
授权 Authorization「你能干什么？」下放权限属性：能用哪些命令、进哪个 VLAN、分什么 IP
记账 Accounting「你干了什么？」记录上线时间、流量、操作日志（计费/审计）
实现方式说明
本地 AAA账号存在设备本地（local-user），小规模；无集中管理
服务器式 AAA设备（NAS）把认证转给中央服务器：RADIUS（UDP 1812/1813，IETF 标准）或 HWTACACS/TACACS+（TCP 49，思科系）
对比项RADIUSHWTACACS / TACACS+
传输UDP 1812/1813TCP 49（可靠）
AA 分离认证+授权合并于一个响应认证、授权、记账完全分离
加密只加密口令字段整报文加密
适合网络接入（WLAN 802.1X、宽带拨号）—— 行业标准设备管理类登录（命令级授权精细）
WLAN 里的 802.1X = supplicant（终端）+ authenticator（AP/AC，只做传话筒）+ RADIUS 服务器，EAP 报文经 AP 用 RADIUS 封装（EAPoL → RADIUS）到服务器完成认证 —— AP 不接触口令，这是「可扩展认证」的设计精髓。
