一、协议全景 · 思维图

先把知识挂到树上：五层各管一件事，下层为上层提供服务。发数据自上而下逐层「套头」，收数据自下而上逐层「剥头」。

二、TCP：三次握手与四次挥手

TCP 面向连接：传数据前先「握手」确认双方收发能力正常，传完再「挥手」优雅断开。以下时序图中左为客户端、右为服务端。

TCP 可靠性三板斧：序号 + 确认（ack）保证不丢不乱；超时重传丢了就重发；滑动窗口控制流量、拥塞窗口控制拥塞。UDP 全都没有 —— 所以快，适合直播、DNS 查询、DHCP。

三、DHCP：开机自动拿到 IP（DORA 四步）

新设备接入网络时连 IP 都没有，靠 UDP 广播完成「要地址 → 给地址 → 确认 → 成交」，四步首字母连起来叫 DORA。

四、ARP：知道 IP，怎么找到 MAC？

同一网段内真正收发帧靠的是 MAC 地址。ARP 用「喊话」的方式问：谁是这个 IP 的，把 MAC 告诉我。

跨网段时不 ARP 对方主机，而是 ARP 默认网关的 MAC —— 出网关就是路由器的事了。免费 ARP（gratuitous ARP）用于主机上线时声明「这个 IP 是我」，兼查 IP 冲突。

五、一次网页访问全流程：DNS + TCP + HTTP

浏览器地址栏敲下 www.example.com 回车后发生了什么 —— 域名换 IP、建 TCP 连接、发 HTTP 请求、收页面，一条链走完。

递归 vs 迭代：主机 → 本地 DNS 是递归（结果必须给到底）；本地 DNS → 根/顶级/权威是迭代（一级级问、一级级被指路）。DNS 走 UDP 53 端口（区域传送才用 TCP 53）。

六、ICMP：ping 背后的报错与探测机制

ICMP 是网络层的「传令兵」：不传业务数据，专职报告网络状况 —— ping 测连通性、TTL 超时、目的不可达都是它。

ping 不通 ≠ 服务不可用：对方防火墙可能只禁了 ICMP 而放行业务端口。反过来 ping 通也只代表网络层可达，应用服务挂了照样打不开网页。

七、OSPF：路由器之间如何互相认识并算路

OSPF 是链路状态路由协议：路由器互相发 Hello 交朋友，交换链路状态数据库（LSDB），各自用 SPF（Dijkstra）算法独立算出最短路径树。

八、STP：交换网络如何避免广播风暴

交换机之间连两条线做冗余，帧就会绕圈繁殖（广播风暴）。STP 用「逻辑断开一条」的方式保住冗余又不绕圈。

九、NAT：一屋私网地址怎么共享一个公网 IP

192.168.x.x 这类私网地址不能在公网跑。NAT 网关在出口处「改写地址」，并对每条连接记一笔账（NAPT 转换表）。

NAT 网关里的转换表（示意）
内部地址 : 端口公网地址 : 端口
192.168.1.10 : 5000202.100.1.5 : 4001
192.168.1.11 : 5100202.100.1.5 : 4002
192.168.1.12 : 5050202.100.1.5 : 4003
源 NAT（上网）把内网源地址改成公网；目的 NAT（端口映射）反过来把公网目的地址映射进来，让外网能访问内网服务器；双向 NAT 两者都做。

十、设备原理：交换机、路由器、集线器

三台设备的本质区别：集线器只放大信号（物理层）、交换机按 MAC 表转发帧（链路层）、路由器按路由表转发包（网络层）。

10.1 交换机：MAC 地址学习 + 转发/过滤

10.2 路由器：查表转发，最长前缀匹配

「IP 不变、MAC 每段重写」：包跨过路由器时源/目的 IP 始终不变（NAT 除外），但帧头每经过一条链路就重写一次 —— 每段链路的源/目的 MAC 都换成该段两端的接口地址。
