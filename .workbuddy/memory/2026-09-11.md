## 修复：进化树编辑器「布局 / …」下拉菜单点了没反应

- **文件**：`src/components/evolution_mind_map.vue`（只改这一个）
- **根因**（两个叠加）：
  1. `.command-bar.floating` 有 `overflow: auto`，会把绝对定位的浮层裁掉；
  2. `.io-dropdown-menu` 原本是**向上**弹出（`bottom: calc(100% + 8px)`），而工具栏 `top: 8px` 贴在最顶部，向上没空间 → 菜单跑到视口外（实测 `top` 为 -124 / -291）。
- **改法**：
  - 菜单改为向下 `top: calc(100% + 8px)`，配 `max-height: min(60vh, 420px)` + `overflow-y: auto`，动画/阴影改方向。
  - 工具栏加 `menu-open` class（`:class="{ 'menu-open': layoutMenuOpen || moreMenuOpen }"`），配 `.command-bar.floating.menu-open { overflow: visible; }`，只在菜单展开时解除裁剪。
- **验证手法（可复用）**：把 SFC 的 `<style>` 原样抽出来（`:deep(...)` 换成裸选择器），按真实 DOM 结构在 Playwright/Chromium 里 `setContent`，用 `elementFromPoint` 判断菜单是否真能点到。修复前后各跑一遍对比 —— 这种「CSS 裁剪导致浮层看不见」的问题，读代码容易看走眼，实测最稳。
  - 注意：`overflow: auto` 的容器会裁剪绝对定位子元素，这是这类 bug 的高频来源。

## 决策：代码运行（Pyodide 方案）的门控

- 用户拍板：**不做 uid 门控**，运行按钮所有读者可见。不写 `isSiteOwner`/`uid === "U000001"` 判断。
- 关键事实（已核实，容易记错）：
  - `src/stores/user.js` 的 `isSiteOwner` = `user.isSiteOwner || uid === "U000001"`；uid 格式是 `U000001`（`server/publicIds.js` 的 `formatPublicId`），**不是数字 1**。
  - 客户端 `v-if` 只是"按钮可见性"，不是安全边界。
  - ⚠️ 修正过一个错判：**Pyodide 并非"发不出网络请求"**。`requests`/`urllib` 因 ssl 桩实现失效，但 `pyodide.http.pyfetch` 直接走浏览器 `fetch`；且 Worker 与页面**同源**，`fetch('/api/...')` 默认带读者 cookie → 恶意代码能以读者身份调站内 API。堵法：跑用户代码前把 Worker 内的 `self.fetch` / `XMLHttpRequest` / `importScripts` patch 成抛错（`pyfetch` 底层就是 `self.fetch`，一刀全断）。
  - 真正隔离 DOM / 本地文件 / cookie 读取的是 Worker 沙箱，与 uid 无关。
- 未定：单块输出上限（建议 512KB，超限只存图片到媒体库、正文放 URL）。
- 拟分四步：①只跑通运行时（不落库/不补全）②接 jedi 补全 ③输出落库 ④对读者开放。

## 新增：专栏合集（collections）

- **需求**：用户可建合集，把相似的作品归到一起；默认公开，可单独设私密。（「收藏夹」= 给现有收藏加分类，**这条还没做**，下一条再做。）
- **关键决定**：合集**只收录作者自己的作品**；文章 + 进化树可以混放在同一合集。和别人的内容相关的归「收藏」，两者不重叠。
- **数据**：`migrations/0024_collections.sql` → `collections`（+`visibility`）+ `collection_items`（`target_type POST|TREE` + `sort_order`）。**没动 posts / content_favorites**。
- **路由形态**：`functions/api/collections/index.js` + `[id].js` + `[id]/items.js`。这种「`[id].js` 与 `[id]/` 目录并存」仓库里有先例（`trees/[id].js` 与 `trees/[id]/contributions.js`），确认可用。
- **可见性规则（重要）**：私密合集对外返回 404（不暴露存在性）；公开合集里的私密作品对访客**自动过滤**；条目计数也按访客身份区分。作品删除/转私密后**条目保留**，只过滤展示。
- **前端**：`src/services/collections.js` + `src/utils/collectionItems.js`（纯逻辑，12 个单测）+ `src/views/collection_detail.vue`（`/collections/:id`）+ `user_space.vue` 加「合集」折叠区（内联新建）。
- **上线前必须做**：`npm run db:migrate:remote`（`wrangler d1 migrations apply DB --remote`），否则接口全 500。
- 测试 78 个全过，构建通过。

### 项目里「专栏 / 收藏」的既有语义（容易搞混）
- **「专栏」= 文章**（`posts`）。`/columns` 页就是文章列表，按 `type`（news / science / 空）筛选。
- **「收藏」早就有了**：`content_favorites(target_type POST|TREE, target_id, user_id)`，**单层无分组**。阅读页有收藏按钮，`user_space.vue` 有「我的收藏」折叠区，接口 `functions/api/user/favorites.js` 里写死 `LIMIT 100`。所以"加收藏夹"= 给它加 `folder_id` 分类列，不是从零做。
