## 部署链路（重要，排查「改了代码线上没变化」）

站点：Cloudflare Pages 项目 `life-tree-wiki`。

- **远程仓库只有 1 个提交** `d4821d6`（2026-09-08 00:13），`origin/main` 至今没动过。
- 本地工作区长期一堆未提交改动 → **Cloudflare 从 GitHub 拉代码构建，本地不 commit/push 就永远不会有新部署**。这是「上传了代码没变化」的根因。
- `dist/` 被 .gitignore 忽略，本机最后一次构建是 09-08 20:03，早于后续所有改动。
- Pages 项目设置：**生产分支是 `production`**（最后部署 5 天前，Source 为空 = CLI 上传）；`main` 分支是预览分支，`main.life-tree-wiki.pages.dev` 是 main 的分支别名，push 到 main 才会更新它。
- 验证线上版本的快速办法：
  - `curl -s https://main.life-tree-wiki.pages.dev/ | grep assets/` 对比本地 `dist/index.html` 的 hash；
  - `curl -s .../assets/index-XXX.js -o f.js && grep -q 关键字 f.js`。
  - 注意：不存在的 `/assets/xxx.js` 会 SPA 回退返回 200 + text/html，别被误导。
- 查部署历史：`npx wrangler pages deployment list --project-name life-tree-wiki --json`（本机 wrangler 已登录）。
- 次级因素：`public/sw.js` 对 `/assets/` 是 cache-first，但资源文件名带 hash，正常不会导致陈旧；`CACHE_VERSION` 目前是 `life-tree-static-v3`。`_headers` 里 `/index.html` 与 `/sw.js` 都是 `no-cache`，缓存**不是**本次的原因。
- 结论（用户澄清后）：用户不是走 GitHub，是「上传到 Cloudflare」。部署记录里 Preview/main 的 Source = 本地 HEAD 的 commit（`wrangler pages deploy` 会自动带上本地 git 元数据），说明**上传的是一份陈旧的 `dist/`** —— 本机自 09-08 20:03 之后就没成功重构建过。
- **教训**：只跑 `wrangler pages deploy dist` 不上传新代码，必须先 `vite build`。本机 `npm run build` 会被沙箱 safe-delete 拦（vite 清空 `dist/assets`），绕法：`npx vite build --outDir dist --emptyOutDir false`（保留旧 hash 文件无害）。

### 分支落错环境（第二个坑，已确认）
用户重新构建后上传，代码确实上线了 —— 但只上到 `main.life-tree-wiki.pages.dev`，`life-tree-wiki.pages.dev` 没变。
原因：`wrangler pages deploy` 不传 `--branch` 时会**自动取本地 git 当前分支（这里就是 `main`）**，而该项目 **Production branch 被设成了 `production`**，于是：
- `--branch main` → Preview 环境 → `main.life-tree-wiki.pages.dev`
- 生产环境 ← 分支 `production` → `life-tree-wiki.pages.dev`
修法二选一：① `--branch production` 传一次；② 控制台把 Production branch 改成 `main`。

验证新代码是否真的上线（别只看 index.html 的 hash，主包 index-*.js 里没有这些标记）：
